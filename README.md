# Lab-Agent — учебная лаборатория (этап v1)

Минимальный удалённый shell для понимания того, КАК устроены такие системы.
Философия лабы: прозрачность. Процесс называется lab-agent.exe, виден в диспетчере,
логирует всё в свою консоль, глушится командой `exit`. Ничего не прячем.

## Правила лабы
1. Запуск только на СВОИХ машинах/ВМ.
2. Никакой маскировки: имя честное, персистентность только штатным видимым schtasks.
3. Цель — понять слой ОС: сокеты, процессы, хэндлы, пайпы, протокол.

## Сборка агента (C, чистый WinAPI, ноль зависимостей)
    gcc -O2 -o lab-agent.exe lab-agent.c -lws2_32

## Запуск
Терминал 1 (оператор):
    python listener.py          # слушает 127.0.0.1:4444
Терминал 2 (хост-машина):
    ./lab-agent.exe 127.0.0.1 4444
Команды набираешь в терминале 1. Выход: набери `exit`.

## Автотест (без ручного ввода)
    python test_e2e.py
Поднимает сервер, запускает агента, прогоняет команды, печатает транскрипт.

## Архитектура v1
    [listener.py]  <--TCP, length-prefix фреймы-->  [lab-agent.exe]
      фрейм: magic "BA01" | type (1=CMD 2=OUT 3=END 4=PING) | len | payload
                                                    └─ CreateProcessW("cmd.exe /c ...")
                                                        └─ Job Object (KILL_ON_JOB_CLOSE)
                                                        stdout/stderr -> пайп (Peek+Wait поллинг)
                                                        + heartbeat-поток: PING каждые 5с

## Что нового в v1 (каждый пункт — урок слоя ОС)
- length-prefix фрейминг: построчный протокол v0 ломался на бинарном выводе,
  содержащем sentinel; длина перед данными решает это (TCP = поток байт).
- md5-проверка в тестах: 3.4 МБ бинарника доезжают бит-в-бит.
- heartbeat: агент шлёт PING каждые 5с — линк считается живым, RTT виден.
- reconnect с exponential backoff + jitter: обрыв не убивает агента, он
  догоняет слушателя; listener просто accept'ит заново.
- Job Object: внуки от `start ...` больше не держат канал — убиваются при
  закрытии job после завершения команды (в v0 это висло).
- Peek+Wait перекачка: конец команды = смерть ребёнка, а не EOF по пайпу
  (EOF не наступит, пока наследованный хэндл держит хоть один живой процесс).
- КРИТИЧЕСКИЙ УРОК v1: перекачка вывода и heartbeat — два потока в ОДИН
  сокет. Без CRITICAL_SECTION PING встраивается посреди OUT-фрейма и рвёт
  поток (нашли md5-тестом на 5-секундном стриме).

## Roadmap (каждый этап = один урок слоя ОС)
- v2: TLS через Schannel + пининг сертификата
- v3: запуск от SYSTEM штатной механикой: `schtasks /ru SYSTEM` на своей машине
- v4: стрим экрана GDI BitBlt своими руками (те же вызовы, что в любом VNC)
- Уроки обороны: Procmon/Sysmon смотрят НАШего агента в реальном времени —
  видно каждый CreateProcess/handle/сокет. Это и есть настоящий уровень понимания.

## Известные ограничения v1 (осознанно, предметы уроков v2+)
- Транспорт plaintext: TLS — тема v2.
- Вывод cmd в CP866, listener декодирует с fallback.
- Если оператор умер, а агент в backoff — сообщение о реконнекте только в его консоли.
